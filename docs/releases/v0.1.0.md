# Kule v0.1.0 — release notes draft

> Draft for review. Not yet released. Fill verified artifact identifiers and acceptance evidence before publishing.

Kule v0.1.0 is planned as an early **single-host** release of a self-hosted MCP service for identity-aware, auditable administration of one approved host. It supports an authenticated Streamable HTTP endpoint, group-based policy, audit-chain verification, and an opt-in, bounded SSH executor.

## Getting started

Install Kule from the [source repository](https://github.com/yesvus/kule) and follow the [first-run guide](../ONBOARDING.md). The `kule init` command creates a local configuration and private state directories, and `kule doctor` performs offline preflight checks. Supply the OIDC client secret and persistent JWT signing key separately through environment or a secret manager. Configure an HTTPS reverse proxy and your OIDC client before connecting a supported MCP client.

## Security and operational defaults

- Host command execution is disabled until explicitly enabled for an authorized operator.
- OAuth/OIDC gates remote privileged use; distinct role groups control tool access.
- Persistent OAuth state and signing keys must be retained across restarts; audit files must be protected.
- An emergency-stop marker can disable tool dispatch, and operators should retain an independent recovery channel.

## Scope and limitations

- v0.1.0 targets one fixed SSH host. The multi-host Hub–Agent enrollment architecture remains planned.
- The public container is built from `Dockerfile.single-host` and excludes the Kubernetes/Argo CD/OpenHands runtime toolchains. Enabling those integrations fails during configuration validation. The original `Dockerfile` remains a separate, explicit legacy/integrator build path.
- The public image runs as UID/GID 10001; persist `/var/lib/kule` and mount its private config, state, and audit files. Behind a TLS reverse proxy outside the container, explicitly configure `server.host = "0.0.0.0"` and `server.allow_pod_bind = true`, and expose port 8795 only on an appropriate trusted interface.
- `kule doctor` is offline: a passing result is not verification of public TLS, OIDC connectivity, actual user login, token refresh, or host execution.
- The container workflow publishes the `sha-<commit>` tag only on pushes to `main`; pull-request builds are not published. There is currently no automatic `v0.1.0` container tag or PyPI publication.
- Source installation from the repository and the immutable GHCR image are the intended artifacts. This version does not imply a PyPI publication, a `v0.1.0` container tag, or an upgrade of existing production deployments.
