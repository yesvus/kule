# Kule v0.1.0 — release notes draft

> Draft for review. Not yet released. Fill verified artifact identifiers and acceptance evidence before publishing.

Kule v0.1.0 introduces a self-hosted MCP service for identity-aware, auditable administration of a configured host. It supports an authenticated Streamable HTTP endpoint, group-based policy, audit-chain verification, and an opt-in bounded SSH executor.

## Getting started

Install Kule from the [source repository](https://github.com/yesvus/kule) and follow the [first-run guide](../ONBOARDING.md). The \`kule init\` command creates a local configuration and private state directories, and \`kule doctor\` performs offline preflight checks. Supply the OIDC client secret and persistent JWT signing key separately through environment or a secret manager. Configure an HTTPS reverse proxy and your OIDC client before connecting a supported MCP client.

## Security and operational defaults

- Host command execution is disabled until explicitly enabled for an authorized operator.
- OAuth/OIDC gates remote privileged use; distinct role groups control tool access.
- Persistent OAuth state and signing keys must be retained across restarts; audit files must be protected.
- An emergency-stop marker can disable tool dispatch, and operators should retain an independent recovery channel.

## Scope and limitations

- v0.1.0 targets one fixed SSH host. The multi-host Hub–Agent enrollment architecture remains planned.
- \`kule doctor\` is offline: a passing result is not verification of public TLS, OIDC connectivity, actual user login, token refresh, or host execution.
- The repository's container workflow publishes the \`sha-<commit>\` tag. There is currently no automatic \`v0.1.0\` container tag or PyPI publication.
- Optional Kubernetes/Argo CD/OpenHands integrations are not part of the single-host onboarding path; confirm the shipping distribution boundary as a release gate.
